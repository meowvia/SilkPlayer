## 零、 审计勘误声明：关于 `CK-01` 杜比视界 Profile 5 线性矩阵链的误判复盘

在初版评估报告中，本审计对 [`DolbyVisionReshape.swift`](file:///Volumes/2T/Projects/SilkPlayer/SilkCoreKit/Sources/SilkCoreKit/Renderer/DolbyVisionReshape.swift)（第 160 行）提出了错误修改建议（建议移除 `dovi_lms2rgb`），导致维护智能体（Antigravity）在 Commit `7baeb84` 中按此执行后，实机播放杜比视界 Profile 5 片源出现严重偏色，随后于 Commit `7d7762d` 紧急回滚恢复为 `r2020_to_p3 * dovi_lms2rgb * rgb_to_lms`。特此正式勘误并撤回该扣分项：

1. **静态审计误判根因**：
   - FFmpeg `libavutil/dovi_meta.h` 的 `AVDOVIColorMetadata` 结构体将 RPU 中的 $3\times3$ 矩阵字段命名为 `rgb_to_lms_matrix`。
   - 初评仅凭静态阅读该字段命名，误认为它已经执行了 LMS 与 RGB 之间的色彩空间转换，进而错误推断再乘一次固定常量矩阵 `dovi_lms2rgb` 属于重复相乘。
2. **杜比视界 Profile 5（IPT-PQ-c2 / ICtCp）真实物理意义**：
   - 第一步经 `nonlinear_matrix`（`ycc_to_rgb`）与 PQ EOTF 线性化后，还原出的是 **线性 LMS 锥体响应空间（Linear LMS）**。
   - RPU 动态元数据里的 `rgb_to_lms_matrix` 实际上是 **LMS 空间内部的 Cross-talk / 微调修剪矩阵**（在绝大多数 Profile 5 标准片源中为单位阵 $\text{diag}(1, 1, 1)$ 或近似单位阵的微调矩阵），**并不负责将 LMS 转换回 Rec.2020 RGB**。
   - 真正将线性 LMS 转换回 Rec.2020 线性 RGB 的核心矩阵，恰恰是固定标准矩阵 `dovi_lms2rgb`（`ITU-R BT.2124`），最后再由 `r2020_to_p3` 映射至 Apple Display P3 线性空间。
3. **结论与教训**：
   - Antigravity 原始实现的 `let linear_matrix = r2020_to_p3 * dovi_lms2rgb * rgb_to_lms` 从数学与色彩科学上完全正确；同时 [`kernel.metal`](file:///Volumes/2T/Projects/SilkPlayer/SilkCoreKit/Sources/SilkCoreKit/Renderer/kernel.metal) 与 [`SilkThumbnailEngine.swift`](file:///Volumes/2T/Projects/SilkPlayer/SilkCoreKit/Sources/SilkCoreKit/Thumbnail/SilkThumbnailEngine.swift) 已补充对 `mapping_idc == 1`（MMR 模式，`c.w >= 0.5`）的中性色度保护守卫。
   - 本案例直接证明：**脱离实机画面播放验证的纯静态代码审计，在面对底层硬件管线与 C 结构体历史命名歧义时存在局限性，必须以实机色彩表现与端到端验证为准绳。**
